# ELF 目录说明

### ELF是一种文件格式，由三部分组成
- 文件头记录整个文件的基本信息，比如程序入口，以及程序头表在哪里。
- 程序头表告诉加载器，每段内容在文件的什么位置、要放到哪个虚拟地址、需要多少内存。
- 程序内容包括机器指令、字符串和有初始值的全局变量等

这个目录涉及两步。**链接时**，链接脚本决定代码和数据运行时的地址，并把信息写进 ELF 文件。**创建进程时**，加载器读取这些信息，把程序装进新进程的内存。即程序怎样链接成 ELF，以及 ELF 怎样装进内存

| 文件 | 作用 |
| --- | --- |
| [app.lds](app.lds) | 应用和系统服务的链接脚本。指定入口为 `app_entry`，并安排代码、数据和堆的虚拟地址。 |
| [egos.lds](egos.lds) | 内核的链接脚本。安排内核的代码和数据 |
| [elf.h](elf.h) | 定义 ELF 文件头、程序头和加载器接口。文件头指出程序头表的位置，程序头描述每段内容怎样加载。 |
| [elf.c](elf.c) | 实现 `elf_load()`。读取程序段，分配物理页并建立映射，再准备参数页和用户栈。 |

## 以运行 echo 为例

1. 编译并链接 `echo.c`，生成 `echo.elf`。`app.lds` 把应用入口安排在虚拟地址 `0x80200000`。
2. `sys_proc` 创建进程时调用 `elf_load()`。加载器按程序头给出的文件位置读取代码和数据，把它们放进分配好的物理页，并映射到程序要用的虚拟地址。
3. 加载器准备 `main()` 的参数页、系统调用参数页和两页用户栈。等 Grass 首次调度这个进程，CPU 才从 [app.s](../../apps/app.s) 的入口开始执行，设置栈指针并调用 `main()`。
