# egos-2000 Project 0 (P0: Hello, World!) 学习笔记与总结

## 一、 核心概念与硬件基础

### 1. 计算机程序的两条基石
- **3 种 CPU 指令类型**：
  1. **整数计算指令**：如 `li`（加载常数）、`addi`/`add`（加法）、逻辑位运算等。
  2. **控制转移指令**：如 `call`/`jal`（函数跳转并记录返回地址）、`ret`（返回）、`bnez`/`beq`（条件跳转）。
  3. **内存访问指令**：如 `lw`/`lb`（从内存加载数据到寄存器）、`sw`/`sb`（将寄存器数据存入内存）。
- **4 种内存区域类型**：
  1. **代码段（Code / .init + .text）**：存放机器指令，只读且可执行。
  2. **数据段（Data / .rodata + .data + .bss）**：存放只读常量（如字符串 `"Hello"`）、全局变量。
  3. **堆区（Heap）**：紧跟在数据段末尾（`__heap_start`），由低地址向高地址向上增长。
  4. **栈区（Stack）**：从高地址 `0x80400000` 开始，由高地址向低地址向下增长。

## 二、 程序启动与栈帧机制

### 1. 程序启动入口 (`hello.lds` & `hello.s`)
- **链接脚本 `hello.lds`**：定义程序第一条指令入口为 `ENTRY(_start)`。
- **汇编入口 `hello.s`**：
  - `li sp, 0x80400000`：把栈指针 `sp` 初始化为高地址 `0x80400000`。
  - `call main`：把返回地址写入 `ra` 寄存器，并跳转到 `main()`。

### 2. 函数序言、结语与 Calling Convention
- **序言 (Prologue)**：
  - `addi sp, sp, -32`：向低地址移动 `sp`，申请 32 字节栈帧。
  - `sw ra, 28(sp)`：将返回地址 `ra` 备份到栈上，防止后续函数调用冲掉 `ra`。
  - `sw s0, 24(sp)`：备份父函数的帧指针 `s0`。
  - `addi s0, sp, 32`：建立当前函数的栈基准点 `s0`。
- **调用约定 (RISC-V Calling Convention)**：
  - 前 8 个函数参数固定用 `a0 ~ a7` 寄存器传递。
  - 函数返回值固定存放在 `a0` 寄存器中。
- **结语 (Epilogue)**：
  - `lw ra, 28(sp)` & `lw s0, 24(sp)`：从栈中恢复之前的 `ra` 和 `s0`。
  - `addi sp, sp, 32`：释放 32 字节栈空间。
  - `ret`：跳转回 `ra` 记录的返回地址。

### 3. 栈指针 `sp` 与 帧指针 `s0` 的物理区别
- **`sp` (Stack Pointer, 栈指针)**：物理上表示“动态流动的栈顶”。在函数运行过程中，随着数据压栈出栈或临时分配，`sp` 的值会经常上下浮动变化。
- **`s0` (Frame Pointer, 帧指针 / 栈基准点)**：物理上表示“固定不动的参考锚点”。在函数序言中通过 `addi s0, sp, 32` 将 `s0` 固定在当前栈帧的最顶端（基准线 `0x80400000`）。在整个函数运行期间 `s0` 数值保持不变，方便编译器使用 `s0 - 20`、`s0 - 24` 等固定偏移量精准定位局部变量，不受 `sp` 浮动的影响。
- **备份 `sw s0, 24(sp)` 的原因**：因为 CPU 全局只有 1 个 `s0` 寄存器。当前子函数在修改 `s0` 前，必须先借用栈内存把父函数的 `s0` 值备份起来，待子函数退出前通过 `lw s0, 24(sp)` 还原给父函数。

## 三、 格式化输出 `printf` 与 `<stdarg.h>` 底层真相

### 1. 可变参数在内存中的物理平铺
当调用 `printf("%s-%d", "egos", 2000)` 时：
- `printf` 一开始用一系列 `sw a1, 4(s0)` ... `sw a7, 28(s0)` 指令，把 `a1~a7` 传进来的变参**连续平铺写入到栈内存中**。

### 2. `<stdarg.h>` 宏的本质
- **`va_list args`**：物理上就是一个 `char*` 指针，保存变参在栈上的物理首地址。
- **`va_start(args, format)`**：算出来 `format` 后面第一个变参的栈地址赋给 `args`。
- **`va_arg(args, type)`**：汇编展开为 4 条指令：
  1. `lw a5, -28(s0)` （读取 `args` 当前指针）
  2. `addi a4, a5, 4` （指针向前推进 `sizeof(type)` 字节）
  3. `sw a4, -28(s0)` （把新指针更新写回 `args`）
  4. `lw a5, 0(a5)` （解引用读取旧指针处的数据）
  *注：`va_arg` 没有发起任何函数调用，纯粹是在物理内存中做指针算术累加。*
- **`va_copy(dest, src)`**：由于 `va_arg` 单向不可逆推进，当需要扫描两遍参数（如先算长度再真正写入）时，必须用 `va_copy` 制作一份独立副本。

## 四、 动态内存分配与堆区管理

### 1. 链接脚本符号与 `_sbrk`
- **链接符号 `__heap_start` / `__heap_end`**：在 C 中用 `&__heap_start` 取出地址，分别代表堆起始物理地址与堆上限（`0x80200000`）。
- **Break 指针 (`brk`)**：记录当前堆的堆顶位置，初始停在 `&__heap_start`。
- **`_sbrk(size)`**：
  1. 检查 `brk + size` 是否超过 `&__heap_end`。
  2. 记下当前旧堆顶 `old_brk = brk`。
  3. 执行 `brk += size` 将堆边界向上抬高。
  4. 返回新申请内存块的首地址 `old_brk`。

### 2. `malloc` 与 `free`
- `_sbrk` 是底层只懂单向拉大内存阀门的接口。
- `malloc` 是高级管家，一次性向 `_sbrk` 要大块内存（如 4KB）建立空闲链表（Free List），按需切分并支持 `free` 垃圾回收。
- 动态分配时需申请 `malloc(len + 1)`，预留 1 字节存放字符串终止符 `'\0'`。

## 五、 ELF 加载器与 4 大内存区域初始化

1. **`hello.elf` 文件**：包含 Program Header（货运清单），标明了代码段与数据段的拷贝目标物理地址及程序入口。
2. **ELF 加载器**：
   - 将代码拷贝至低地址 `0x80000000`（代码段）。
   - 将字符串常量拷贝至代码段末尾（数据段 `.rodata`）。
   - 在数据段末尾标记 `__heap_start`，将 `brk` 停在起点（堆区）。
   - 将 CPU 的 `sp` 指针强行赋值为高地址 `0x80400000`（栈区）。
   - 将 CPU 的 PC 指针置为 `0x80000000`，启动程序。
3. **地址偏移原因**：当代码量变大或编写的代码指令条数发生变化时，代码段（`.text`）体积改变，会推挤紧跟其后的只读数据段（`.rodata`），从而导致字符串常量在内存中的物理地址发生微小偏移。
